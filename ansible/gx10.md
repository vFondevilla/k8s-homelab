# GX10 DS4

`gx10.yml` reconciles the DS4 configuration on the existing ASUS GX10 as
`victor`. The inventory override uses `10.1.1.230` because some resolvers still
return the old address. All tasks run as the SSH user; sudo is not required on
the current host.

## Managed configuration

- The captured `ds4-serve` launcher and Codex model catalog.
- DeepSeek V4 Flash with the DSpark drafter, CUDA, and a 524288-token context.
- An OpenAI-compatible API at `http://10.1.1.230:8000/v1`, listening on all IPv4
  interfaces. The DS4 server has no built-in authentication; this is a trusted
  LAN endpoint.
- The `ds4-server.service` user unit, enabled startup, and user lingering so the
  service runs after logout and at boot.
- Automatic restart, a model-readiness check, and bounded startup retries.

Launcher, catalog, or unit changes notify one handler to reload systemd and
restart DS4. Unchanged runs leave the running model process alone. Normal runs
verify `/v1/models`; check mode predicts changes without starting inference.

## Prerequisites and scope

The playbook requires Ubuntu 24.04 on ARM64, the existing `victor` account,
working NVIDIA drivers/CUDA libraries, curl, and these files under the user's
home directory:

- `code/ds4/ds4-server`: the existing CUDA build (observed v0.6.2, commit
  `d183482`).
- `gguf/DeepSeek-V4-Flash-IQ2XXS-w2Q2K-AProjQ8-SExpQ8-OutQ8-chat-v2-imatrix-0731.gguf`.
- `gguf/DSpark-drafter-Q2K-Q8-0731.gguf`.

Prerequisite checks avoid checksumming the large model files. The playbook
does not download model weights, rebuild DS4, or provision a fresh operating
system. It does not manage GPU/OS upgrades, DNS, networking, firewall rules, or
Tailscale. No credentials or model weights are stored in this repository.

## Run

Install Ansible Core on the controller and authenticate the 1Password CLI with
access to the SSH key. From the repository root:

```bash
gx10_key=$(mktemp)
trap 'rm -- "$gx10_key"' EXIT
op read 'op://2w4dyciswfctvp42ue7hn5znam/v55zxzq5vdr3hba7gs5syzgryy/private key' > "$gx10_key"
ansible-playbook -i ansible/inventory.yml ansible/gx10.yml \
  --private-key "$gx10_key" --check --diff
```

Remove `--check --diff` to reconcile the host. If Task is installed, equivalent
commands are `task -d ansible gx10:check -- --private-key "$gx10_key"` and
`task -d ansible gx10 -- --private-key "$gx10_key"`.

SSH host-key verification stays enabled. The known host key must be established
before running unattended. If the LAN address changes, update
`host_vars/gx10.yml`.

## Operations

On GX10 as `victor`:

```bash
systemctl --user status ds4-server.service
journalctl --user -u ds4-server.service -f
```

From another lab machine:

```bash
curl --fail http://10.1.1.230:8000/v1/models
```

## Validation

Validated on GX10 on 2026-11-15 with Ansible Core 2.20.11. Syntax, launcher, and
JSON checks passed. Live check mode reported no changes; two normal runs each
completed with `ok=13 changed=0 failed=0`. The DS4 process kept the same PID,
and model discovery remained reachable from another lab machine.
