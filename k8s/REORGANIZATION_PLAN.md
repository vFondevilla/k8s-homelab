# Kubernetes reorganization record

Status: **repository reorganization complete**

Scope: `k8s/` and the previous top-level `cluster-api/` experiments

## Result

The repository now has one Kubernetes ownership model.

Deployable components use `k8s/apps/`.

Argo orchestration uses `k8s/argocd/`.

Manual GitOps bootstrap resources use `k8s/bootstrap/`.

Cluster lifecycle APIs, profiles, claims, and examples use `k8s/fleet/`.

The reorganization did not activate a staged Application or tenant ApplicationSet.

## Completion criteria

The repository meets these structural criteria:

- Git tracks no numbered cluster root.
- Git tracks no deployable `cloud-underlay` root.
- Git tracks no top-level component directory under `k8s/`.
- Each deployable component has a base and role overlay structure.
- Argo resources stay outside component directories.
- Active management Applications use normalized source paths.
- Fleet examples stay outside Argo discovery.
- Generated caches and private configuration stay outside Git.

## Tenant bootstrap constraint

The tenant Cilium overlay still contains a fixed Kubernetes API endpoint.

Dynamic Kamaji tenants require a different endpoint for each generated cluster.

A static `ClusterResourceSet` cannot substitute that endpoint.

Therefore, the staged tenant Cilium ApplicationSet remains outside the active Argo root.

This constraint is an operational feature gap. It is not a repository ownership gap.

## Ephemeral lifecycle constraint

The repository defines the request fields for an ephemeral tenant profile.

No controller currently enforces expiry or removes an Argo cluster registration.

Do not create an unattended ephemeral tenant until that controller exists.

This constraint is an operational feature gap. It is not a repository ownership gap.

## Safe activation procedure

Use this procedure for each staged component:

1. Record the live resource inventory.
2. Render the staged overlay.
3. Compare resource names, namespaces, and immutable fields.
4. Review generated Secrets and persistent storage.
5. Add only the selected wrapper to an Argo Kustomization.
6. Keep automated pruning disabled.
7. Refresh Argo and review the complete diff.
8. Sync without pruning.
9. Make sure that recorded UIDs remain equal.
10. Enable the approved sync policy after two clean refresh cycles.
